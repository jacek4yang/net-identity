# 发布前页面验收

当前候选在 PR #92。页面验收和正式发布是两个独立步骤：用户完整验收最终页面并明确批准后，才允许进入签名、商店更新或发布。测试通过不能替代用户验收。

## 操作路径

1. 弹窗点“添加代理”，填写主机和端口。支持单独字段或明确协议的地址，不猜测协议，不接收地址内的密码。
2. 无认证时不必展开认证栏。需要认证时单独填写账号密码，凭据仅留在本次 Firefox 会话。
3. “保存”只保存配置；“保存并启用”明确切换线路。设置页面的“应用”使用已保存配置。
4. 新建 SOCKS 配置默认代理 DNS；新建代理默认严格 WebRTC。高级选项保留可见说明，已有配置不被重置。
5. 身份与地图、高级设置、运行详情默认收起。地图默认离线，联网地图需要主动操作与适用的同意。
6. 弹窗和设置页可切换中英文，不改变代理、不丢弃未保存表单。用户输入的名称、主机、IP、时区标识符和技术策略标识不翻译。
7. 弹窗、设置页和 README 都能找到 LINUX DO。点击才打开外部网站；页面不嵌入该站脚本、图片或追踪资源。

## 验收图片

图片来自真实 Firefox 和虚构本地配置，无真实凭据。示例禁用 GeoIP 查询，所以显示未验证、部分生效或空白 IP 是诚实的诊断，不是测试失败被隐藏。

完整资格还包括错误反馈、重复点击、语言切换时保留编辑状态、返回与页面恢复、窄窗口和缩放。未验证的项目不能以截图代替通过结论。

## 需明确保留的限制

- 严格 WebRTC 可能使缺少 TURN/TCP 代理路径的音视频通话不可用。
- HTTP/HTTPS 不支持 Firefox 的 SOCKS `proxyDNS` 开关。
- 扩展不是操作系统 VPN，也不能保证所有 Firefox 系统请求都能取消。
- 地理位置与时区是网页兼容性适配，不承诺不可检测或消除所有浏览器指纹。
- 浏览器原生权限提示使用 Firefox 自己的语言，不受扩展手动语言选择控制。

批准后如再修改可见页面或交互，应重新展示受影响部分。论坛宣传内容不得把尚未发布的功能描述为商店已上线。
