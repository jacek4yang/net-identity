# Net Identity：行为边界与恢复规则

本文描述当前候选版本，不代表已经发布。它管理 Firefox 内的代理和页面可见身份，
不管理操作系统网络，也不承诺所有浏览器内部请求都能被拦截。

## 三种状态必须分开

- **编辑中的草稿**：正在输入的值。自动检测可以预览，不保存、不切换普通网页流量。
- **已保存的配置**：用户保存的版本。保存本身不改变当前生效线路。
- **已启用的配置**：最后一次明确启用的快照。网络中断、恢复和后台重启都不能
  擅自用更新的草稿或未启用版本替换它。

## 网络中断与恢复

1. 选中的代理仍然是普通、非绕过请求的必经路径。失败不会触发 Direct 回退或换代理。
2. 后续正常请求提供持续成功证据后，健康状态恢复。没有流量时，不保证立即显示正常。
3. 健康恢复不得重写保存的配置、代理端点、DNS、WebRTC、凭据、位置、时区、启用代际或版本。
4. 不重放失败的 HTTP 请求，不在后台偷偷 Apply、Refresh 或发起无限探测。
5. 单个站点错误不等于代理故障；旧代际、缓存和被取消请求不得污染当前恢复判断。
6. 网络恢复只证明近期连接可用，不证明出口 IP 没变，也不等于新一次 GeoIP 验证。
   当前保留上次身份观测；需要重新观测时由用户明确刷新。手动位置和时区继续保留。

## 操作与权限

| 操作             | 可以做什么                                         | 不能顺带做什么                                |
| ---------------- | -------------------------------------------------- | --------------------------------------------- |
| 输入有效代理端点 | 在必要数据许可下，经草稿代理向 ipwho.is 做有界预览 | 保存配置、改变普通网页线路、默认直连兜底      |
| 保存             | 保存可编辑配置；凭据仅存会话                       | 自动启用该版本                                |
| 保存并启用       | 保存当前表单并启用成功保存的版本                   | 保存失败后启用旧值                            |
| 选择已有线路     | 启用该线路的已保存配置                             | 把别的草稿一起保存                            |
| 刷新身份         | 按已启用配置重新观测                               | 启用未保存修改、覆盖明确的手动身份设置        |
| 关闭 / Off       | 明确停止扩展线路与身份控制，释放 WebRTC 控制       | 伪装为仍受保护；承诺 Firefox 系统代理也已关闭 |
| 网络健康恢复     | 更新状态和诊断                                     | 重设任何用户配置、重新授权权限                |
| 语言或主题变化   | 改变界面显示                                       | 改变线路、身份或存储中的网络策略              |

Options 中关闭 Public IP / GeoIP 可停止草稿检测与对应运行时查询；弹窗快速添加按设计
自动预览。有效草稿的检测不是“本地连通性测试”：ipwho.is 会看到草稿代理的出口 IP。
首次地图加载需要明确同意；记住自动加载后，只为可见地图申请新的、与当前线路绑定的
会话，按视野取地图数据。地图恢复不能更改身份、绕过缺失凭据或自动弹出权限授权。
取消加载、关闭编辑器或切换线路会废弃旧会话；旧响应不能写回新编辑状态。

## 默认值与用户选择

新代理默认启用 SOCKS DNS、proxy-only WebRTC 和自动身份。HTTP(S) 没有等同于 SOCKS
proxyDNS 的 Firefox 开关。默认值不覆盖已有配置中的显式选择；自定义绕过规则仍然有效。
proxy-only WebRTC 可能让没有可用代理/TURN 路径的通话失败，不能承诺任何应用都无影响。

后台挂起恢复保留已启用快照。完全退出 Firefox 后，会话凭据丢失；需要认证的普通请求
保持阻断，必须重新提供凭据并明确启用。不能偷偷改成匿名账号或 Direct 来制造“恢复”。

## 平台与发布边界

- 显式绕过的地址遵循 Firefox 的原有网络设置，不属于代理必经保证。
- Firefox 保护的内部服务请求不能全部取消；代理服务端必须拒绝匿名访问才能保证账号身份。
- 页面身份依赖注入能力，浏览器拒绝注入的页面/框架不在保证范围内；不承诺匿名或不可检测。
- 状态正常、测试通过都不等于零缺陷。签名包、普通 Firefox 安装和 Mozilla 审核需单独验证。
- 合并、选择新版本、打标签与公开发布需要单独确认；边界检查本身不执行发布。

## 验证依据

- `tests/activation.test.ts`：SOCKS4/5、HTTP/HTTPS × 自动/手动身份；故障及恢复前后
  校验生效快照、未启用修改、本地/会话存储、WebRTC 调用次数、GeoIP 调用次数均不变。
- `tests/proxy-health.test.ts`：持续恢复证据、过期样本和缓存过滤。
- `tests/migrate.test.ts`：升级保留合法配置与已启用快照，清除旧的持久凭据值。
- `scripts/e2e-fail-closed.mjs --flap`：真实 Firefox 三轮中断/恢复，HTTP/HTTPS/WS/WSS/DNS，
  零直接访问哨兵、无重放、稳定身份/代际/版本/代理/WebRTC。
- `scripts/run-draft-checks.mjs`：检测 B 时普通流量仍走 A、认证纠错、无兜底、草稿不持久化。
- `--delayed-init`：延迟初始化不得覆盖先前输入或取消已完成预览。

每次修改都以新提交自己的 CI 结果为准，不用旧提交通过结果代替。

## 加密保险库补充边界（本次候选版）

用户首次设置主密码后，配置、已保存凭据和实际启用凭据一起加密保存。
退出 Firefox 后数据仍在，但可能需要重新解锁；未启用保险库时仍采用原有会话凭据模式。
升级不会自动重置配置或替用户设置密码。损坏或不支持的数据保留原件并报告错误。
解锁恢复已启用快照，不应用尚未启用的新编辑；断网恢复不变更保险库或身份。
之前关闭的路由在锁定时仍关闭，之前启用的路由在解锁前阻断普通可观测请求。
完整格式、备份和平台限制见 [ENCRYPTED-VAULT.md](ENCRYPTED-VAULT.md)。
